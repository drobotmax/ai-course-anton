Теория

Как устроены LLM

📖 ~30 минФаза 1, Урок 1

Прежде чем строить AI-агентов, нужно понимать, как работает ядро — Large Language Model. Это не магия и не разум. Это математическая машина, которая невероятно хорошо предсказывает следующее слово.

Как LLM генерирует текст

Представь автозаполнение в телефоне, но в миллиард раз мощнее. LLM прочитала весь интернет и научилась: если написано "столица Франции —", то дальше скорее всего "Париж". Это называется авторегрессивная генерация — модель генерирует по одному токену за раз.

🔑 Ключевые понятия

Токен — кусочек текста (примерно ¾ слова). "Привет мир" = 2–3 токена.

Контекстное окно — сколько токенов модель "видит" за раз. GPT-4o: 128K, Claude: 200K, Gemini: 1M+.

Temperature — параметр "креативности". 0 = детерминированный, 1 = творческий, >1 = хаотичный.

Top-p — из скольких вариантов следующего слова модель выбирает. 0.1 = очень точно, 0.9 = разнообразно.

Трансформер — архитектура под капотом

Все современные LLM (GPT, Claude, Gemini, Llama) построены на архитектуре Transformer (2017, Google). Ключевая идея — механизм внимания (attention): модель взвешивает важность каждого слова для каждого другого слова в тексте. Это позволяет понимать контекст на расстоянии.

Почему LLM "галлюцинирует"

LLM не знает, что правда, а что нет — она знает, что звучит правдоподобно. Если модель не видела ответ в данных, она сгенерирует что-то похожее на правду. Отсюда — "галлюцинации". Это не баг, это фундаментальное свойство.

💡 Практический вывод

Никогда не доверяй LLM факты без проверки. Но для генерации текста, кода, идей, анализа — это мощнейший инструмент. Задача AI-разработчика — выстроить систему, которая компенсирует галлюцинации (RAG, проверки, guardrails).

Сравнение моделей 2026

  • GPT-4o (OpenAI) — универсал, быстрый, хорош для всего. Мультимодальный.
  • Claude Opus/Sonnet (Anthropic) — лучший для длинных текстов, кода, анализа. Огромный контекст (200K).
  • Gemini 2.0 (Google) — рекордное контекстное окно (1M+), интеграция с Google.
  • DeepSeek V3 — open-source, хорош в математике и коде, бесплатный.
  • GigaChat (Сбер) — русскоязычный, знает российский контекст.
  • Llama 3 (Meta) — open-source, можно запускать локально.

Практика

Мультимодальность: не только текст

📖 ~20 минФаза 1, Урок 3

Современные LLM работают не только с текстом. GPT-4o, Claude и Gemini понимают изображения, аудио, PDF, таблицы и даже видео. Это меняет правила игры — AI становится универсальным инструментом.

Что умеют мультимодальные модели

  • Анализ изображений — загрузи фото, скриншот, диаграмму → AI опишет, объяснит, извлечёт данные
  • Работа с PDF — загрузи договор, отчёт, презентацию → AI суммирует, ответит на вопросы
  • Распознавание аудио — Whisper (OpenAI) транскрибирует речь с точностью 95%+
  • Генерация изображений — DALL-E 3, Midjourney, Stable Diffusion
  • Генерация голоса — OpenAI TTS, ElevenLabs — текст в естественную речь

Теория + Практика

Анатомия идеального промта

📖 ~30 минФаза 2, Урок 1

Промт-инжиниринг — это навык номер один для работы с AI. Качество ответа на 80% зависит от качества запроса. Это как разница между "сделай сайт" и детальным ТЗ с макетами.

Плохой vs хороший промт

❌ Плохо
"Напиши коммерческое предложение"
✅ Хорошо
"Ты — опытный B2B копирайтер. Напиши коммерческое предложение для IT-компании, которая предлагает внедрение AI-чатботов для банков. Целевая аудитория — директора по цифровизации. Тон: профессиональный, но не сухой. Объём: 1 страница. Структура: боль → решение → кейс → CTA."

5 элементов идеального промта

  1. Роль — кем должен быть AI ("Ты — senior Python-разработчик с 10 годами опыта")
  2. Контекст — что AI нужно знать ("Я делаю Telegram-бота для ресторана...")
  3. Задача — что конкретно сделать ("Напиши функцию, которая...")
  4. Формат — как должен выглядеть ответ ("В формате JSON / таблицы / пошагово")
  5. Ограничения — чего НЕ делать ("Не используй внешние библиотеки", "Максимум 200 слов")

Few-shot: покажи пример — получи формат

Самый мощный приём: покажи AI 1–3 примера того, что хочешь получить. Модель повторит формат.

// Few-shot промт для классификации Классифицируй обращение клиента: Пример 1: "Не могу войти в аккаунт" → Категория: Авторизация, Приоритет: Высокий Пример 2: "Когда будет скидка?" → Категория: Продажи, Приоритет: Низкий Пример 3: "Приложение крашится при оплате" → Категория: Баг, Приоритет: Критический Теперь классифицируй: "Хочу изменить email в профиле"

Теория + Практика

Продвинутые техники промтинга

📖 ~35 минФаза 2, Урок 2

Базовый промтинг — это 20% возможностей. Дальше — техники, которые используют AI-инженеры в продакшне.

1. Chain-of-Thought (CoT) — цепочка рассуждений

Добавь "Думай пошагово" или "Рассуждай шаг за шагом" — и точность ответов на сложные задачи вырастает на 30-50%.

// Без CoT — модель часто ошибается: В магазине было 23 яблока. Купили 3 пакета по 8 яблок и продали 15. Сколько осталось? // С CoT — пошаговое рассуждение: В магазине было 23 яблока. Купили 3 пакета по 8 яблок и продали 15. Сколько осталось? Рассуждай пошагово, показывая каждое вычисление.

2. ReAct — рассуждение + действие

Паттерн для агентов: модель думает ("мне нужно узнать X") → действует (вызывает инструмент) → наблюдает (анализирует результат) → повторяет.

3. Self-Consistency — самопроверка

Попроси модель решить задачу 3 раза разными способами и выбрать ответ, который совпал чаще всего.

4. Tree-of-Thought — дерево мыслей

Для сложных задач: попроси рассмотреть несколько подходов, оценить каждый, выбрать лучший.

Предложи 3 разных подхода к решению этой задачи. Для каждого подхода: 1. Опиши стратегию в 2 предложениях 2. Оцени плюсы и минусы 3. Дай оценку по шкале 1-10 Затем выбери лучший подход и реализуй его.

5. Structured Output — структурированный вывод

Попроси ответ в JSON, Markdown-таблице, XML — и модель выдаст ровно в нужном формате.

Проанализируй этот отзыв клиента и верни результат в JSON: { "sentiment": "positive/negative/neutral", "topics": ["тема1", "тема2"], "urgency": 1-5, "suggested_action": "текст" }

Маркетинг и контент

Роль: Ты — контент-маркетолог с опытом в B2B SaaS. Задача: Напиши 5 постов для Telegram-канала нашей компании. Контекст: Мы продаём CRM для малого бизнеса. ЦА — владельцы компаний 20-100 чел. Формат: Каждый пост: заголовок (до 10 слов) + текст (до 150 слов) + CTA. Тон: Разговорный, экспертный, без канцеляризмов. Ограничения: Не используй слова "уникальный", "инновационный", "лучший на рынке".

Анализ и стратегия

Роль: Ты — бизнес-аналитик McKinsey. Задача: Проведи SWOT-анализ нашей компании. Контекст: [вставь описание бизнеса, рынка, конкурентов] Формат: Таблица 2×2 (Strengths, Weaknesses, Opportunities, Threats). По каждому пункту: факт + рекомендация. Затем: ТОП-3 стратегических приоритета на следующий квартал.

Код и техническое ревью

Роль: Senior Python developer, специалист по code review. Задача: Проведи ревью этого кода. Формат ответа: 1. Критические проблемы (баги, безопасность) 2. Качество кода (читаемость, naming, структура) 3. Производительность 4. Рекомендации по улучшению с примерами кода Ограничения: Не переписывай весь код. Покажи только изменённые участки. [вставь код]

RAG: базы знаний для AI

📖 ~35 минФаза 6, Урок 1

RAG (Retrieval-Augmented Generation) — технология, которая позволяет AI отвечать на вопросы по твоим данным: документы, FAQ, базы знаний. Это самая востребованная задача в AI-бизнесе.

Как работает RAG

  1. Загрузка — берём документы (PDF, DOCX, сайт, FAQ)
  2. Chunking — разбиваем на куски по 500-1000 символов
  3. Embedding — превращаем каждый кусок в вектор (массив чисел)
  4. Хранение — складываем в векторную базу данных (ChromaDB, FAISS)
  5. Поиск — при вопросе ищем похожие куски по косинусному сходству
  6. Генерация — подставляем найденные куски в промт LLM

RAG на практике: AI-консультант с базой знаний

📖 ~45 минФаза 6, Урок 2

Собираем полноценный RAG-пайплайн: загрузка документов → chunking → embeddings → поиск → генерация ответа.

from langchain_community.document_loaders import PyPDFLoader from langchain.text_splitter import RecursiveCharacterTextSplitter from langchain_openai import OpenAIEmbeddings, ChatOpenAI from langchain_community.vectorstores import Chroma from langchain.chains import RetrievalQA # 1. Загрузка PDF loader = PyPDFLoader("company_docs.pdf") docs = loader.load() # 2. Разбиение на куски splitter = RecursiveCharacterTextSplitter(chunk_size=1000, chunk_overlap=200) chunks = splitter.split_documents(docs) # 3. Создание векторной базы vectorstore = Chroma.from_documents(chunks, OpenAIEmbeddings()) # 4. RAG-цепочка qa = RetrievalQA.from_chain_type( llm=ChatOpenAI(model="gpt-4o"), retriever=vectorstore.as_retriever() ) # 5. Задаём вопрос answer = qa.invoke("Какая политика возвратов?") print(answer["result"])

Продвинутый RAG: reranking, hybrid search, eval

📖 ~30 минФаза 6, Урок 3

Базовый RAG работает на 60-70%. Продвинутые техники доводят до 90%+.

Ключевые техники

  • Hybrid Search — комбинация keyword (BM25) + vector search. Ловит и точные совпадения, и смысловые.
  • Reranking — после поиска переранжируем результаты через cross-encoder модель.
  • Contextual Chunking — добавляем контекст (заголовок, раздел) к каждому чанку.
  • Self-RAG — модель сама решает, нужен ли поиск для ответа.

AI-агенты: что это и зачем

📖 ~30 минФаза 7, Урок 1

Агент = LLM + инструменты + память + логика принятия решений. Обычный чат-бот отвечает. Агент — действует: ищет информацию, вызывает API, отправляет сообщения, принимает решения.

Паттерн ReAct

Основа всех агентов: Think (рассуждаю) → Act (вызываю инструмент) → Observe (смотрю результат) → Think (что дальше?) → ...

LangGraph: строим агента

📖 ~45 минФаза 7, Урок 2

LangGraph — фреймворк для построения агентов как графов: ноды (действия) + рёбра (переходы) + состояние (память).

from langgraph.graph import StateGraph, MessagesState, START, END from langgraph.prebuilt import ToolNode, tools_condition from langchain_openai import ChatOpenAI from langchain_core.tools import tool @tool def search_knowledge_base(query: str) -> str: """Ищет информацию в базе знаний компании.""" # Здесь RAG-поиск return f"Результат поиска для: {query}" llm = ChatOpenAI(model="gpt-4o").bind_tools([search_knowledge_base]) def agent(state: MessagesState): return {"messages": [llm.invoke(state["messages"])]} graph = StateGraph(MessagesState) graph.add_node("agent", agent) graph.add_node("tools", ToolNode([search_knowledge_base])) graph.add_edge(START, "agent") graph.add_conditional_edges("agent", tools_condition) graph.add_edge("tools", "agent") app = graph.compile()

AI SaaS: продукт по подписке

📖 ~25 минФаза 10, Урок 2

Проекты на заказ — это хорошо. Но SaaS (подписка) — это recurring revenue. Создай AI-продукт, который платит каждый месяц.

Идеи AI SaaS

  • AI-секретарь для стоматологий — записывает на приём, отвечает на вопросы
  • AI-помощник для юристов — анализ договоров, поиск по законодательству
  • AI-рекрутер — скрининг резюме, первичное интервью через чат-бота
  • AI-контент-менеджер — генерация постов для SMM по расписанию

Unit-экономика

Средний AI SaaS: $50-500/мес за клиента. Себестоимость (API + серверы): $5-50/мес. Маржа: 80-90%. Цель: 100 клиентов = $5K-50K/мес recurring.
